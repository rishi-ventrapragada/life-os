# SESSION_7.md — Step 7: Habits section — CRUD + daily completion checkbox + persistence behind real auth (two tables this time; streaks/grid are NOT this step)

**Goal:** build the Habits section as a full vertical slice — two new tables (`habits` and `habit_checks`, each born with `user_id` + owner-only RLS in the same DDL) plus their UI and Supabase wiring — reusing the data-layer + design patterns proven in Goals (Step 3) and Tasks (Step 6), gated behind the real auth from Step 5. Per PRD §8 Step 7 and §9: a habit has name + life area + add/edit/archive; each habit shows **today's completion checkbox**; checking today writes exactly one `habit_checks` row, unchecking removes it, and a `unique(habit_id, check_date)` constraint makes a day impossible to double-log. `check_date` is a plain `yyyy-mm-dd` IST date from `getTodayIST()` (Law 3).
**Done when (from PRD §8):** checking today's box **creates one `habit_checks` row**; unchecking **removes it**; the day is **unique per habit** (no double-log, enforced by the DB constraint, not just the UI); habit CRUD (add/edit/archive) + today's checked state **persist across a hard refresh**; and **both new RLS tables survive the adversarial two-account cross-read/write test**.
